# Add a process to skweeb

An app is a folder, a param schema and three functions. Everything else —
panels, vault, gallery, lineage, thumbnails, publishing, gamepad input — is
inherited from `core/`. If an app is writing any of that itself, the port has
gone wrong.

Read `docs/core-api.md` before the first edit. Read the `sequence-stage` skill
too if the app records, replays or exports frames — do not re-derive it.

## The folder

```
apps/<name>/
  index.html      loads core, then main.js. Opens and works with no vault.
  main.js         defineParams, registerApp, the sketch
  params.js       the schema, once it outgrows main.js
  manifest.json   generated by a script. Never scan a directory at runtime.
  STATUS.md       works now / broken / next single step / parked
```

## The schema first, always

Write the parameters before the sketch. The panel, the recipe, the gallery
filters and the gamepad bindings all fall out of it, so a parameter that is not
in the schema is a parameter that cannot be saved.

```js
export const params = defineParams("<name>", {
  cell:   { type: "range", min: 4, max: 64, default: 12, label: "cell size" },
  source: { type: "object", accepts: ["still", "sequence"] },
});
```

`type: "object"` is how an app eats what another app made: it renders a vault
picker and records the choice in `parents` by itself.

## The three functions

```js
registerApp("<name>", {
  version: "1.0.0",
  serialize() { return { ...params.values } },
  restore(recipe) { params.set(recipe) },
  render(recipe, { width, height, frame, rng, load }) { /* headless */ },
});
```

`render()` is the hard one and the valuable one. It may not read the clock, the
DOM, `Math.random()` or p5's `random()` — only `rng`. That is what makes a still
re-printable at a larger size and a loop re-exportable at any frame rate. Write
it at the same time as the sketch, not after: retrofitting it means untangling
every place state was read from the page.

## Porting an existing sketch

In this order, because each step makes the next one smaller:

1. **Inventory the globals.** Every `let` at file scope is either a param (goes
   in the schema), state (goes in the app object) or a constant. Three piles,
   nothing left over.
2. **Instance mode.** One p5 from `core/libs/`. No `function setup()` at file
   scope, no globals crossing files.
3. **Seed it.** Replace every `random()` with `rng()`. This is the step people
   skip and the one that cannot be added later without re-testing everything.
4. **Params to schema**, deleting the hand-written panel HTML and CSS as each
   control moves.
5. **`render()`**, extracted from `draw()`.
6. **Vault in, vault out** — replace hardcoded asset paths with `type: "object"`
   params.

Hardcoded root-absolute paths (`loadFont("/fonts/…")`) break under the suite's
server and are worth grepping for first.

## Before calling it done

- Opens standalone at `apps/<name>/index.html` with `vault/` absent.
- No file over 400 lines. No global crosses a file boundary.
- Save, reload, `restore()` — the piece comes back identical.
- Same recipe and seed rendered twice give identical bytes.
- `STATUS.md` rewritten with one concrete next step.
